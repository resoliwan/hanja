# 짧은 선분 기반 다대다 획 매핑 v3 — 구현과 평가

평가일: 2026-11-06

## 범위

사용자의 ‘1,2,3,4’를 숫자 一·二·三·四로도 해석할 수 있어, 네 숫자와 앞서 비교한 用을 함께 평가했다. SCUT 5세트에서 총 77레코드, 중복 제외 72궤적이다.

한 입력을 여러 SVG 획에 붙이거나, 여러 입력을 한 SVG 획에 붙일 수 있다. 이 구현은 CNN 학습이나 실시간 인식이 아닌 오프라인 후보 답안지 생성 실험이다. 기존 v1/v2 결과와 원본 자료는 보존했다.

## 구현

`stroke_mapping/segment_matcher.py`는 v2의 전체 배정 검색과 별개의 단순 국소 비교 방식이다.

1. 원본과 SVG를 글자 전체 기준으로 정규화한다. 방향 중앙값으로 기울기를 보정하고 전체 경계 상자를 맞춘다. 양축 크기가 충분할 때는 제한된 비등방 크기 보정도 사용한다. 一처럼 높이가 거의 없는 경우에는 수직 흔들림을 확대하지 않는다.
2. 입력 경로를 글자 크기의 약 0.025 간격으로 재샘플링한다. 손을 뗀 구간은 연결하지 않는다.
3. 각 짧은 선분 중심을 각 SVG 경로에 투영한다. 비용은 거리 + 0.12 × (1 - 방향 코사인의 절댓값)이다. 역방향도 같은 후보로 인정하며 작성 순서는 점수에 사용하지 않는다.
4. 거리 0.16 초과, 방향 코사인 0.65 미만, 후보 간 비용 차이 0.008 미만은 미대응으로 둔다. 같은 라벨 양쪽에 둘러싸인 짧은 모호 구간만 보완하고, 길이 0.05 미만의 고립 대응은 제거한다. 다른 입력 간 보완은 하지 않는다.
5. 같은 라벨의 연속 선분을 합친다. 미대응 구간 양옆이 서로 다른 획이면 `connector_candidate`로 표시하되, 정답으로 인정한 연결선이라는 뜻은 아니다.
6. 각 대응 조각의 투영 위치와 정렬된 길이를 이용해 SVG 경로상의 작은 커버 구간을 근사한다. 커버 구간의 **합집합** 길이를 사용하며, 최초/최후 대응 사이의 빈 구간을 채우지 않는다. 정답 획을 가로지르는 것만으로 해당 획 전체를 쓴 것으로 보지 않는다.
7. 모든 정답 획 커버 ≥45%, 미대응 입력 길이 ≤45%면 잠정 `accepted`다. 이 기준은 정확도나 정답 확률이 아니다. 실제 오매핑이 발견되어 **학습 사용은 모든 결과에서 `review_required`**로 남긴다.

원본 위치는 정렬 전의 균일 샘플 번호를 추적하여 `original_start/end`의 원본 점 번호(0부터)와 보간 비율로 환산한다. 비등방 정렬 후 경로 길이를 원본 경로 길이로 착각하지 않도록 했다. 재샘플링을 거친 근사 위치이며 원본 꺾임 경계에 대한 정답 주석은 아니다.

주요 출력은 `segment_mappings`다. 입력 번호, 구간 경계, SVG 번호, 미대응 사유, 정답 경로의 대응 구간을 기록한다. `proposed_mappings`는 입력별 대상 번호의 집합을 펼친 요약이며, 입력 번호를 키로 하는 단일 값 사전으로 바꾸면 안 된다.

## 실행

```sh
.venv/bin/python tools/handwriting/build_stroke_answers.py --method segments
.venv/bin/python tools/handwriting/evaluate_segment_answers.py
.venv/bin/python -m unittest tools.handwriting.stroke_mapping.test_mapping tools.handwriting.stroke_mapping.test_segments
```

기본 결과는 `experiments/handwriting/results/stroke-mapping-segments-v3/`다. v2 비교 방식은 `--method whole`로 실행한다. v3는 기존 NumPy/fontTools/Pillow 환경을 사용하며 새 패키지를 설치하지 않았다.

- `answers.jsonl`, `templates.json`, `summary.json`: 원본, 후보 구간 대응, 설정, 출처 해시.
- `review.html`: 구간별 색상, 커버 범위, 미대응 사유, 원본 구간 표.
- `segments-U*.png`: 대응 색상을 표시한 전체 77개 검토 이미지.
- `visual-U*.png`: 매핑 색 없는 원본 비교 이미지.
- `evaluation.json`: 기존 시각적 매핑과의 대조 및 회귀 결과.
- `resolution-and-order-checks.jsonl`: 입력 순서/방향 반전, 절반 간격 샘플링 비교.
- `visual-evaluation.md`: 이번 직접 시각적 검토에서 발견한 구체적 오류.

## 결과: 자동 채택과 정확도를 구분

| 글자 | 전체 | 자동 채택 | 보류 |
|---|---:|---:|---:|
| 一 | 14 | 14 | 0 |
| 二 | 16 | 6 | 10 |
| 三 | 10 | 6 | 4 |
| 四 | 15 | 5 | 10 |
| 用 | 22 | 10 | 12 |
| 합계 | 77 | 41 | 36 |

이 표는 **커버 기준을 통과한 수**다. 자동 채택에 오매핑이 섞여 있으므로 41개를 올바른 답안지로 세면 안 된다.

v2와 겹치는 62개에서 자동 채택은 48→36으로 줄었다. 기존 보류 중 5개가 새로 통과했고, 기존 채택 중 17개가 보류로 바뀌었다. 새로 통과한 사례는 一의 덧그림 1개와 用의 이어쓰기 4개(동일 궤적 중복 포함)다. 새로운 통과가 정확한 구간 매핑을 의미하지는 않는다.

기존에 직접 시각적으로 확인한 일대일 샘플 48개 중, 입력별 대상 획 번호 집합이 일치한 것은 40개였다. 나머지 8개는 모두 用이다. **用의 기존 11개 중 8개에서 다른 획 번호가 추가되거나 바뀌었다.** 그 8개 중 4개는 v3에서도 자동 채택되어 있다. 집합 일치만으로 연결선 구간이나 경계가 정확하다고 볼 수도 없다.

## 시각적 판단

어시스턴트가 착색 시트 11장, 총 77개를 직접 확인했다. 이전에 같은 자료와 구현을 보았으므로 독립 인간 정답이나 맹검은 아니다. 점별/구간별 독립 정답이 없어 정확도는 null로 유지한다.

- 一는 대체로 단일 대상 대응이 안정적이다. 덧그림도 같은 대상에 연결될 수 있다. 이것은 글자 자체의 인식 정확도를 뜻하지 않는다.
- 二·三은 짧은 획을 해당 번호에 붙였어도 SVG 경로 길이 대비 커버가 낮아 보류하는 사례가 많다. 전체 크기를 맞추는 것만으로 각 획의 상대 길이 차이가 해결되지 않는다.
- 四·用은 획이 가까운 곳에서 국소 라벨이 바뀌며, 되돌림이나 연결 동작 일부가 다른 정답 획에 붙는다.
- 用의 이어 쓴 두 가로획을 초록/보라 구간으로 나누는 기능은 동작한다. 하지만 연결 대각선 일부까지 초록/보라/중앙 세로 색으로 잘못 채운다.
- 커버 조건만으로 이 오매핑을 걸러내지 못한다. 특히 四의 아래 획이 내부 꺾인 획으로 바뀌는 사례도 자동 채택된다.

**결론: 다대다 대응을 표현할 수 있게 되었지만, 현 v3를 v2의 안정적인 일대일 답안지를 대체할 수준으로 판단하지 않는다.** 기존 전체 획 대응을 유지하면서 이어쓰기 구간에만 제한적으로 적용하는 방법이나, 최소한의 구간 연속성 제약이 다음 실험 후보다. 이번에는 결과를 좋게 보이게 하려고 커버 기준을 완화하지 않았다.

## 검증

기존 15개와 신규 8개, 총 23개 동작 테스트 통과. 신규 검증은 1입력→2정답, 2입력→1정답, 用 내부 가로 이어쓰기, 입력 순서/방향 변경, 가로지르기 거절, 커버 합집합, 비등방 정렬 후 원본 위치 추적, 잘못된 좌표를 포함한다. 합성 동작 검증은 실제 필기 정확도를 대체하지 않는다.

실제 77개에서 입력 순서와 각 획 방향을 동시에 뒤집어도 대상 번호 집합과 채택 상태가 모두 유지됐다. 선분 길이를 절반으로 바꾸면 대상 번호 집합은 74/77개에서 유지됐고, 채택 상태는 77/77개에서 유지됐다. 이 수치 역시 정답 정확도가 아니라 변형에 대한 일관성이다.
