# 一·二·三·用 오프라인 획 답안지 생성 — v2

갱신일: 2026-11-06

## 목적과 범위

정답 글자가 알려진 완성 SCUT 필기에서 `입력 획 번호 → SVG 획 번호`를 생성한다. 실시간 인식, 글자 맞히기, 글씨 품질 채점, CNN 학습은 하지 않는다. 一·二·三·用만 지원한다.

**대응 판단과 필체 특성을 분리한다.** 一의 한 입력은 출처 라벨이 정확하다는 전제에서 SVG 1번에 대응한다. 수직선이나 낙서까지 一로 인식했다는 뜻이 아니다. 다른 글자도 입력 라벨을 전제로 하므로 잘못된 출처 라벨을 검출하는 인식기로 사용하면 안 된다.

원본 자료와 기존 학습/평가 분할은 변경하지 않았다. SCUT 평가 자료로부터 만든 후보를 향후 학습에 쓰면 기존 평가와 겹치지 않도록 분할을 다시 설계해야 한다. 이번 출력은 자동 생성 후보이며 학습 실행이나 데이터 분할을 포함하지 않는다.

## 입력 처리

- SCUT `onHCCTestDB-TradChar.zip` 5세트의 POT 좌표와 문자 라벨을 읽는다. POT 코드와 TXT 라벨을 대조하고 실제 작성 순서, 획 내부 점 순서, 레코드 번호/바이트 위치를 보존한다. 시간/필압은 없다.
- simpledic의 SVG에서 clip-path가 붙은 애니메이션 중심 경로만 읽는다. 외곽선은 사용하지 않는다. 부모 좌표 변환을 적용하고 clip ID 번호를 기준으로 표준 획순을 복원한다.
- SVG 애니메이션 경로에는 붓 모양을 표현하는 말단 우회가 있을 수 있다. 실제 사람의 필기 궤적/속도와 동일시하지 않는다.
- 글자 전체를 균일 비율로 정규화한다. 획별 위치/길이를 따로 지우지 않는다. 원본과 SVG의 경계 상자 기준이므로 절대적인 글자 칸 위치를 검증하지는 않는다.
- 정규화된 경로는 64점으로 보존하고 비교 시 24/32/48점으로 재샘플링한다. 원본 좌표도 별도로 저장한다.

## v2 매핑

### 공통 기울기

각 획 중앙 구간의 떨어진 점들 사이 방향을 구한다. 방향이 수평/수직 축에서 벗어난 각도의 중앙값으로 획별 기울기를 얻고, 다시 획들 사이 중앙값으로 글자 전체 기울기를 추정한다. 획마다 따로 회전하지 않고 전체를 동일하게 보정한다. 시작/끝의 짧은 갈고리나 불균일 점 밀도가 추정을 지배하지 않도록 한다.

이 추정은 대체로 똑바로 놓인 한자를 전제로 한다. 90도 회전이나 심한 비선형 변형까지 복원하는 알고리즘이 아니다.

### 一·二·三

- 一: 입력 1획일 때 라벨에 의해 대응이 유일하다. `correspondence_basis=unique_given_label`.
- 二·三: 기울기를 보정한 뒤 각 획 중앙 구간의 y 중앙값으로 위아래 순서를 구한다. SVG에도 같은 처리를 해서 순위를 연결한다.
- 획 중심 간격이 0.03보다 작으면 구조적으로 모호하다고 보류한다. 모양 차이의 절대 점수는 대응 탈락 조건이 아니다.

### 用

왼쪽 세로, 바깥 꺾임, 내부 가로 두 개, 중앙 세로라는 구조를 SVG 좌표로 비교한다. 특정 입력 순번에 역할을 고정하지 않는다.

각 입력/후보 쌍의 비용:

- 0.40 × 대표 중심 위치 차이
- 0.20 × 가로/세로 크기 차이
- 0.25 × 수평/수직 이동 비중 차이
- 0.15 × 중심을 맞춘 경로의 DTW 차이 (정/역방향 중 작은 값)

5획의 120가지 일대일 배정을 모두 계산한다. 전체 비용은 `0.7 × 평균 획 비용 + 0.3 × 획 중심 간 상대 변위 차이`다. 작성 순서는 점수에 넣지 않는다. 최선/차선 차이 0.01 미만은 동률에 가까운 모호한 구조로 보류한다. 이 임계값과 가중치는 초기 가정이며 확률 보정된 값이 아니다.

### 안정성 검사

사전에 정한 7조건에서 매핑을 반복한다.

1. 32점, 양끝 10% 제외 (기본)
2. 양끝 포함
3. 양끝 20% 제외
4. 24점
5. 48점
6. 입력 기울기 추정 -5도
7. 입력 기울기 추정 +5도

모든 조건에서 동일하고 모호하지 않은 연결만 채택한다. `stability`는 이 조건들 사이 일치 비율이지 정답 확률이 아니다. 위 변형만으로 모든 종류의 불안정성을 검증한 것은 아니다.

### 필체 특성과 보류

기울기, 대응 SVG보다 큰 되돌림/굽음, 큰 템플릿 차이 등을 `quality_flags`에 따로 저장한다. 用의 원래 꺾인 획 자체를 문제로 표시하지 않는다. 대응은 안정적이어도 필체 특성 때문에 학습 사용은 `review_required`일 수 있으며, 이것은 매핑 실패와 다르다.

획 수 불일치/좌표 오류는 계속 보류한다. 이어쓰기의 한 입력을 여러 SVG 획으로 분할하거나 덧그림을 합치는 작업은 이번 범위에 포함하지 않았다. 대상 글자 범위를 늘리기 전에 이 기능이 필요하다.

## 출력과 실행

```sh
.venv/bin/python tools/handwriting/build_stroke_answers.py --method whole
.venv/bin/python -m unittest tools.handwriting.stroke_mapping.test_mapping -v
.venv/bin/python tools/handwriting/evaluate_stroke_answers.py
```

생성기는 `--scut`, `--svg-dir`, `--characters`, `--out`을 지원한다. `--method whole`의 기본 출력은 `experiments/handwriting/results/stroke-mapping-123-yong-v2/`다. 현재 생성기 기본 모드는 v5이며 [별도 문서](stroke-answer-target-mapping-v5.md)를 참고한다. 기존 환경을 사용한다.

- `answers.jsonl`: 원본 좌표/출처, 대응/제안, 필체 특성, 안정성 검사별 결과. 번호는 1부터 시작한다. `mappings`는 채택 샘플에만 있으며 `proposed_mappings`는 검토용이다.
- `templates.json`, `summary.json`: SVG 좌표 스냅샷, 출처 SHA-256, 설정, 결과. 출처 중복을 추적할 `trajectory_sha256`도 저장한다.
- `review.html`, `overview.png`: 전체 매핑/필체 특성 검토.
- `visual-U*.png`: 원본의 모든 점을 그린 흑백 비교 이미지. 점수/매핑색 없이 실제 입력 번호와 SVG 번호만 표시한다.
- `visual-assessments.jsonl`: 어시스턴트가 직접 이미지를 보고 기록한 대응. 생성기가 이 파일을 만들거나 덮어쓰지 않는다.
- `visual-evaluation.json`, `order-invariance.jsonl`: 위 시각적 평가와의 대조, 작성 순서를 섞고 방향을 뒤집은 검사 결과.

평가기는 미리 존재하는 시각적 평가 파일을 요구한다. 자동 답안을 정답으로 복사하지 않는다. 원본 궤적 해시가 달라졌으면 평가를 중단한다.

## 실행 결과

| 글자 | 전체 | 서로 다른 원본 궤적 | 매핑 채택 | 보류 |
|---|---:|---:|---:|---:|
| 一 | 14 | 14 | 13 | 1 |
| 二 | 16 | 15 | 15 | 1 |
| 三 | 10 | 9 | 9 | 1 |
| 用 | 22 | 20 | 11 | 11 |
| 합계 | 62 | 58 | 48 | 14 |

보류 14개는 모두 획 수 불일치다. 一·二·三의 v1 채택은 27/40이었으며 v2는 37/40이다. 기존의 모양 차이에 의한 보류 10개가 대응 후보로 채택되었다. v1 결과는 `stroke-mapping-123-v1`에 보존했다. v1 때의 실행 방법은 이제 현재 코드를 재현하므로, 과거 비교에는 보존된 산출물을 사용해야 한다.

用에서는 5획으로 구분된 11개가 모두 안정적으로 연결되었다. `trad3-14611`과 `trad5-14580`은 실제 작성 순서가 `1,2,5,3,4`에 해당하며 정확히 그 번호로 연결되었다. **두 레코드는 동일 궤적의 중복**이므로 두 개의 독립 성공 사례로 세어서는 안 된다. 나머지 11개는 여러 정답 획이 1~4개 입력으로 연결되어 있다.

## 평가와 한계

15개 동작 테스트 통과: 一·二·三의 모든 순서/방향 조합 58개 하위 사례, 기울기/갈고리, 유일 대응과 품질의 분리, 用의 순서 변경·역방향·회전, 중복 가로획 보류, 정상 꺾임의 품질 처리, SVG/POT 파서 검증을 포함한다.

실제 매핑 가능한 48개를 대상으로 입력 순서 변경과 순서+획 방향 반전을 각각 적용한 **96건이 모두 기존 시각적 대응과 일치**했다. 一처럼 순서 변경에 의미가 없는 단일 획도 이 숫자에 포함되어 있다.

어시스턴트 시각적 평가에서는 채택된 48개 대응에 동의했고, 나머지 14개는 일대일 분할/추가 입력 처리가 필요하다고 판단했다. 一·二·三은 이전 시각적 기록과 대조했고 用 22개는 새 흑백 시트 3장을 직접 확인했다. 같은 어시스턴트가 알고리즘을 구현했으므로 독립 인간 정답이나 엄밀한 맹검이 아니다. 단순한 글자와 소수 샘플에 대한 결과이며 학습에 사용하지 않은 필기자/복잡한 다른 한자로 일반화한 정확도는 측정하지 않았다.

따라서 `summary.json`의 `accuracy`는 여전히 null이다. 시각적 평가와의 일치 수, 자동 채택률, 변형 검사 일치율을 각각 별도로 보고한다.
