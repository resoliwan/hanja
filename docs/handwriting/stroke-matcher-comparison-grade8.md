# 8급 결정적 합성 필기 비교 — 미세 중복 획 지원

2026-11-06

## 변경

SVG 하나를 입력하면 생성기 v2가 10개 변형과 정답 대응을 만든다. SVG 바이트의 SHA-256으로 난수 시드를 정하므로 같은 SVG와 버전에서 항상 같은 결과가 나온다. 중복 사례는 원본을 그대로 복사하지 않고, 첫 획에 약간의 위치 이동과 작은 곡선 흔들림을 추가한 후 마지막에 덧쓴다. 원본과 덧쓴 입력은 모두 같은 SVG 획이 정답이다.

매칭기는 원래 연속된 입력 묶음만 후보로 사용했다. 이제 서로 떨어져 있는 입력이라도 전체 경로가 거의 겹치면 반복 묶음 후보를 추가한다. 글자 전체 정규화 좌표에서 32개 재표본점의 평균 거리 0.020 이하, 최대 거리 0.035 이하, 길이 비율 0.85 이상을 사용한다. 진행 방향이 반대인 덧쓰기도 후보 검사에서는 허용하며, SVG와의 최종 비교에는 진행 방향 비용이 남아 있다.

반복 묶음은 각 입력과 SVG의 비용을 개별 계산해 평균한다. 같은 경로를 여러 번 이어 붙여 가짜 회귀 동작을 만들지 않는다. 동일 입력 구간의 중복 소유는 여전히 금지하며, 여러 입력이 같은 SVG 획을 소유할 수 있다. 서로 거의 같은 입력을 모순되는 SVG 획으로 나눠 배정하는 조합도 막는다. 다만 정답 SVG에 실제로 가까운 별개 획이 존재하면 별도 배정을 허용한다. 원래 개별 후보도 유지하므로 모든 가까운 선을 무조건 합치지 않는다.

## 실행

```sh
.venv/bin/python tools/handwriting/compare_stroke_matchers.py --grade 8 --out experiments/handwriting/results/stroke-matcher-comparison-grade8-v2
```

Simpledic 대한검정회 8급 30자에서 300건을 실행 시 생성했다. 사천성의 실제 `EvaluateWritingStroke` 및 `ShooterStrokeMatcher`와 의존 모델을 그대로 복사해 Dart로 실행했다. 사천성 앱은 수정하지 않았다. 입력과 SVG는 양쪽에 동일하게 전달하고 정답 주석은 평가기만 사용한다. 카메라나 이미지 판독은 사용하지 않았다.

## 결과

서로 다른 글자 30건은 전체 글자가 다르면 어떤 획도 색칠하지 않는 정책 검사다. 공유 획의 색칠을 허용할 수 있어 주 매핑 성능과 분리한다. 나머지 270건의 결과는 다음과 같다.

| 평가 | 사천성 | SVG 묶음 |
|---|---:|---:|
| 입력→SVG 대응 전체 정답 | 169/270 | 269/270 |
| 입력→SVG 대응 오류 | 101/270 | 1/270 |
| 최종 SVG 색칠 집합 정답 | 234/270 | 270/270 |
| 미세한 중복 획 대응 정답 | 0/30 | 30/30 |

SVG 묶음의 남은 오류는 `人 / extra_ink`에서 추가 입력 3을 SVG 2번에 연결한 경우다. 정상 입력의 연결과 최종 색칠 집합은 맞지만 불필요한 연결이 하나 생겼다. 다른 글자 30건에서는 양쪽 모두 일부 획을 연결하므로 엄격한 전체 글자 거절 정책 기준은 0/30이다. 이 정책까지 합치면 사천성 169/300, SVG 묶음 269/300이다.

연결 단위(270건) TP/FP/FN: 사천성 1069/37/161, SVG 묶음 1230/1/0. 이는 필기 단위 정답 건수와 분모가 다르다.

기존 실제 필기 검토 자료 54건은 재검사에서도 54건 모두 기존 정답 대응과 일치했다. 자동 테스트 51개를 확인했다. 반복 획, 꺾인 반복 획, 여러 번 덧쓰기, 가까운 정상 두 획의 분리, 원본/미세 중복 생성의 재현성을 포함한다.

## 해석 범위

이 결과는 정답 SVG를 변형한 개발용 합성 사례의 성능이다. 새로운 사람 필기에 대한 일반화 정확도나 구간 경계의 정확도가 아니다. 실제 필기 54건 역시 이전에 AI가 검토한 개발 자료다.

사천성은 모든 입력을 순차 처리한 최종 결과, SVG 묶음은 완성 필기를 한 번 처리한 결과다. 누적 입력의 중간 단계 정확도는 이번에 비교하지 않았다. Python과 Dart의 실행 환경도 달라 실행 시간만으로 알고리즘 고유 속도의 우열을 확정하지 않는다. 一의 이어쓰기 사례는 같은 획을 나눴다가 다시 연결하는 항등 변형이다.

결과 파일은 `experiments/handwriting/results/stroke-matcher-comparison-grade8-v2/`에 있다. `cases.jsonl`은 입력과 정답, `evaluated.json`은 개별 정오, `summary.json`은 지표와 소스 해시, `real-handwriting-regression.json`은 기존 실제 필기의 재검사 결과다.
