# 사진에서 글자 획을 복원하는 모델 학습 계획

작성: 2026-11-04. 상태: 작은 파일럿 학습·평가 완료. 앱 변경·배포 미실행.

## 목표와 범위

사용자가 선택한 한 글자 컬러 사진에서 배경·색·조명을 제거해 원본의 글자 획을 복원한다. 복원 결과는 기존 4,998자 인식기에 전달한다. 첫 버전은 한 글자 영역을 입력으로 받으며, 전체 사진에서 글자 위치를 찾거나 여러 글자를 읽는 기능은 포함하지 않는다.

사진 RGB → 소형 획 복원 모델 → 글자 마스크 → 기존 크기·여백 정규화 → 기존 한자 인식기 → 후보 10개.

기존 필기 입력은 복원 모델을 거치지 않는다. 인식기의 가중치를 먼저 고정해 복원 모델만의 기여를 측정한다. 읽을 수 없는 부분을 그럴듯한 획으로 만드는 것보다 보이는 획을 정확히 보존하는 것이 목표다.

## 확인된 자산

- `resources/handwriting/datasets/korean-hanja5000-v1`: 원본 이미지·문자 라벨·분할 정보.
- `experiments/handwriting/results/hanja5000-head-only-v1/settings.json`: 4,998자, train 317,494 / validation 19,576 / evaluation 99,807. 과거 실행 설정의 수치이며 실행 전 로더로 다시 집계한다.
- `tools/handwriting/hanja3500_dataset.py`: 기존 로더. SCUT 평가 전용 정책과 중복 제외 규칙 유지.
- `apps/dic/assets/hanja.onnx`: 현재 배포용 인식기, 입력 1×1×128×128.
- `apps/dic/lib/adapter/recognition/ink_normalization.dart`: 모바일 정규화 계약. 배경 -1, 획 +1, 내부 최대 크기 97픽셀.
- Python `GlyphTransform`에는 밝기 조절·테두리 기반 반전이 있지만 앱 사진 전처리와 동일하지 않다. 학습·앱 전처리 일치 검증을 별도 작업으로 포함한다.
- `experiments/handwriting/results/photo-color-probe-20261104`: 두 글자로 만든 32개 합성 조건의 진단 실험. 자동 반전·이진화 Top-1 23/32, Top-10 26/32. 전체 사진 정확도의 추정치로 사용하지 않는다.

## 1. 데이터와 정답 만들기

원본 글자를 깨끗한 배경 위의 연속값 획 마스크로 정리한다. 안티앨리어싱·가는 획을 보존하고 원본 종이 질감이 마스크에 섞이지 않는지 출처별로 표본 검수한다. 원본 전체를 임의의 고정 밝기값으로 잘라 정답으로 삼지 않는다.

각 학습 항목은 `(컬러 합성 사진, 정답 획 마스크, 문자 라벨, 원본 ID, 배경 ID, 변환 seed)`로 구성한다.

1. 원본 마스크에 위치·크기·약한 기울기·원근 변환을 적용한다.
2. 같은 좌표의 정답 마스크를 보관한다.
3. 글자 색과 배경을 합성한다.
4. 입력 사진에만 조명·흐림·압축·노이즈를 적용한다.

색과 노이즈가 없는 마스크가 복원 정답이다. 공간 변환은 입력과 정답에 같이 적용해 픽셀 위치를 맞춘다. 첫 버전에서 크게 왜곡된 글자를 정자체로 바꾸는 문제까지 동시에 학습하지 않는다. 좌우·상하 반전은 문자 의미를 바꾸므로 사용하지 않는다.

### 합성 조건

| 축 | 포함할 조건 |
|---|---|
| 글자 색 | 검정·흰색·빨강·파랑·녹색, 임의 RGB, 채도·밝기 변화, 다색 그라데이션 |
| 배경 | 밝고 어두운 단색, 종이·책 표지·나무·천 등의 질감, 절차적으로 만든 무늬 |
| 색 대비 | 밝기 차이가 큰 경우, 밝기는 비슷하지만 색상이 다른 경우, 낮은 대비 |
| 조명 | 가운데 밝은 띠, 좌우·방사형 그라데이션, 부분 그림자, 반사광 |
| 촬영 | 약한 흐림·움직임 번짐·JPEG 압축·센서 노이즈, 작은 크기에서 확대 |
| 선택 영역 | 여백 변화, 중심 이탈, 주변 글자의 일부·선·테두리 |
| 빈 입력 | 글자 없는 배경·무늬. 목표 마스크는 빈 화면 |

주변 글자를 넣는 경우 중심의 선택 글자만 정답으로 정의하고, 여러 글자 중 대상을 구분할 수 없는 합성은 제외한다. 심한 잘림·빛 번짐으로 획이 완전히 사라진 예는 별도 불가독 평가에 사용한다. 존재하지 않는 정보를 복원할 수 있다고 가정하지 않는다.

학습 합성은 배치마다 생성해 저장량을 줄인다. 검증·최종 평가 합성은 seed를 고정해 매번 같은 이미지를 사용한다. 실제 배경을 도입하면 출처와 사용 조건을 기록한다.

### 누출 방지

색을 바꾸기 **전에** 원본 단위로 train/validation/test를 확정한다. 같은 원본·group_id·중복 픽셀이 여러 분할에 나타나지 않도록 기존 제외 규칙과 검증 분할을 재사용한다. 동일 배경 사진에서 자른 조각도 배경 원본 ID 단위로 분리한다. 평가용 폰트·SCUT 이미지는 복원 모델에도 학습시키지 않는다. 추가로 일부 문자 종류를 복원 학습에서 제외하는 진단 세트를 만들어 특정 글자 암기 여부를 확인한다.

## 2. 복원 모델

- 시작 후보: 작은 U-Net 계열 인코더–디코더. 3채널 RGB 256×256 → 1채널 256×256 획 확률.
- 입력을 회색조로 만들지 않는다. 밝기가 비슷한 빨강·초록 등을 분리할 수 있도록 색 정보를 유지한다.
- 출력의 연속값을 `흰 배경·검은 획` 이미지로 변환하고 기존 정규화를 거쳐 인식기에 전달한다. 출력 임계값·크롭 기준은 검증 세트에서 결정하고 최종 평가 전에 고정한다.
- 시작 손실: 획 가중 BCE + Dice. 빈 마스크도 안전하게 처리하고, 가는 획 누락·획 연결 오류를 표본 검사한다. 가중치는 검증으로 결정한다.
- 1단계에서는 픽셀 복원만 학습한다. 필요할 때만 고정 인식기의 문자 손실을 보조로 추가하고 복원 품질 저하 여부를 비교한다. 이 경우 미분 가능한 정규화 경로가 필요하며 기존 이산 크롭을 그대로 역전파할 수는 없다.
- 초기 크기 예산: 파라미터 약 1–3M을 목표로 설계하되 실제 연산량·기기 속도로 조정한다. GAN 등 생성 품질 위주 손실은 초기 범위에서 제외한다.

U-Net 원 논문: https://arxiv.org/abs/1505.04597 . 구조 선택의 근거이며 이 과제에서의 정확도를 보장하는 자료는 아니다.

## 3. 단계별 실험

### A. 기준선과 파이프라인 확인

현행 처리 / 회색조만 / 자동 반전·이진화 / 깨끗한 정답 마스크를 직접 넣는 경우를 같은 평가 세트로 측정한다. 마지막 항목은 복원이 완벽해도 기존 인식기가 틀리는 사례를 구분하는 기준이다. 합성 RGB와 마스크가 픽셀 단위로 정렬되는지, 글자 클래스와 원본 ID가 일치하는지 확인한다.

### B. 작은 실험

획 수와 자형을 나눠 500자를 고르고 클래스당 최대 40개 원본, 총 최대 20,000개를 사용한다. 새 복원 모델을 RGB 입력으로 약 3 epoch 학습한다. 시작값은 AdamW, learning rate 1e-3, batch 32이며 메모리·검증 추이에 따라 조정한다. epoch당 합성 표본 수와 seed를 기록한다.

먼저 100배치로 속도·메모리를 측정해 실제 소요 시간을 산출한다. 현재 기기의 MPS 사용 가능 여부를 확인하며, 확인 전 완료 시간을 약속하지 않는다. 검증 데이터의 배경·폰트가 달라져도 기준선보다 좋아지는지 확인한 뒤 전체 학습으로 진행한다.

### C. 전체 4,998자 학습

기존 train 분할을 클래스·원본 출처별로 균형 있게 샘플링한다. 시작 예산은 epoch당 100,000개 합성 표본, 최대 10 epoch, validation 개선이 3 epoch 없으면 조기 종료다. 예산은 파일럿 속도와 학습 곡선을 보고 확정한다. 깨끗한 입력도 섞어 이미 읽기 쉬운 글자를 망가뜨리지 않게 한다.

쉬운 단색부터 시작해 질감·조명·그라데이션의 비율을 높인다. RGB 모델과 회색조 입력 모델을 소규모 대조 실험해 색 정보를 보존하는 효과를 분리한다. 결과가 정체되면 어려운 조건의 합성 빈도를 조절한다. 같은 증강을 활용한 인식기 직접 미세조정은 이후 비교 후보이며 최초 구현에 같이 넣지 않는다.

### D. 실제 사진 평가

책·포장·간판·화면·필기 등에서 읽을 수 있는 한 글자 사진을 초기 목표 500장 이상 수집하고 정답 문자를 검수한다. 같은 물체를 연속 촬영한 사진은 한 그룹으로 분리한다. 이 세트에는 합성 원본과 독립적인 이미지가 필요하다.

검증용 사진과 최종 테스트 사진을 먼저 분리한다. 검증 실패를 보고 합성 방식을 조절할 수 있지만, 잠근 테스트 사진으로 반복 튜닝하지 않는다. 사진 정답은 문자 라벨만 있어도 인식 성능을 평가할 수 있다. 픽셀 복원 지표에는 별도 마스크 라벨이 필요하므로 작은 부분집합만 추가 라벨링한다.

합성·실사 분포 차이가 남을 수 있으므로 합성 정확도만으로 제품 적용하지 않는다. 참고: https://arxiv.org/abs/2303.06994 (합성과 실제 열화 간 차이를 다룬 복원 연구).

## 4. 평가와 진행 기준

주 지표는 기존 인식기까지 연결한 최종 Top-1·Top-10과 문자별 macro 평균이다. 조건별 결과, 원본을 깨끗하게 넣었을 때 대비 하락폭, 표본 수와 원본 그룹 기준 신뢰구간을 함께 제시한다. 마스크 Dice·획 누락/추가 사례는 원인 진단용이다. 배경 픽셀이 대부분이라는 이유로 전체 픽셀 정확도만 보고 성공 판정하지 않는다.

다음은 **제안하는 진행 목표**이며 예상 정확도가 아니다.

- 보지 않은 합성 조건에서 최선의 기존 전처리보다 Top-1 10%p 이상 개선.
- 깨끗한 입력의 Top-1 하락 1%p 이내.
- 실제 사진에서 기준선보다 Top-1이 개선되고, 특정 색·조명 조건의 악화가 없는지 확인. 제품 목표는 읽을 수 있는 사진 Top-1 90%, Top-10 98%로 두고 실제 결과로 채택 여부를 판단.
- 빈 배경의 허위 획·후보 발생률을 별도로 보고한다. 기존 분류기는 항상 후보를 내므로, 복원 마스크가 비어 있는 경우 추론을 중단하는 정책이 필요하다. 낮은 신뢰도 판단은 검증으로 보정한다.
- ONNX 변환 전후 결과 일치와 실제 iPhone에서 속도·메모리 확인. 추가 지연 p95 100ms 이내를 초기 목표로 하되 기기 모델·조건을 함께 기록.

목표 미달이면 조건별 실패를 모아 합성 개선 또는 실사 보강을 한 차례 진행한다. 계속 실패하면 사진 위에 직접 따라 쓰는 흐름을 기본/대안으로 검토한다. 불가독 입력에서 정답을 추측하도록 강제하지 않는다.

## 5. 코드와 결과 위치

- `tools/handwriting/photo_restoration/`: 합성, paired dataset, 소형 모델, 학습, 평가, 내보내기. 기존 원본 로더를 조합하고 모델과 앱 책임을 섞지 않는다.
- `resources/handwriting/datasets/photo-restoration-v1/`: split·배경 출처·고정 평가 manifest. 기존 원본 데이터는 변경하지 않는다.
- `experiments/handwriting/results/photo-restoration-v1/`: 설정·hash·seed·체크포인트·조건별 성적·실패 이미지·성능 측정.
- 앱 통합은 효과 검증 후 `apps/dic/lib/adapter/photo/`에 복원 처리 추가. RGB 디코딩·정규화 계약을 명시하고 기존 필기 경로는 유지한다.

기존 데이터와 앱 모델을 그대로 보존한 채 파일럿 모델의 성공 여부를 먼저 확인한다. 계획 승인 여부와 무관하게 이 문서 작성만으로 학습이나 배포를 시작하지 않는다.

## 2026-11-04 맥 속도 사전 측정

현재 M4 Pro / 메모리 24GB에서 1,095,553 파라미터의 임시 U-Net, RGB 256×256, batch 16, FP32, AdamW, BCE+Dice를 측정했다. warmup 3회 후 10 step 중앙값 0.203초, 약 78.8 images/sec. MPS driver allocated memory 약 3.11GiB이며 전체 앱/시스템 최고 메모리를 뜻하지 않는다. 합성 텐서만 사용했고 실제 원본 학습은 하지 않았다.

- 작은 실험: 20,000 draws × 3 epoch 가정 시 순수 연산 약 13분. 데이터 합성·검증을 포함한 계획 범위 30–60분.
- 전체: 100,000 draws/epoch 순수 연산 약 21분. 10 epoch 순수 연산 약 3.5시간. 합성·검증 포함 계획 범위 5–10시간.
- 매 epoch 전체 원본 317,494개를 모두 사용한다면 10 epoch 순수 연산만 약 11.2시간. 위 5–10시간은 이 설정에 해당하지 않는다.

포함 오버헤드 범위는 실측이 아닌 여유를 둔 추정이다. 최종 모델 크기·합성 구현·검증 횟수·동시 작업·열 상태에 따라 달라진다. 데이터 준비, 코드 구현, 실제 사진 수집, 반복 실험 및 ONNX·기기 검증 시간은 별도다. 본 학습 전 실제 데이터 파이프라인 100배치로 추정을 갱신한다. 측정 결과와 실행 스크립트는 experiments/handwriting/results/photo-restoration-m4pro-*에 보관한다.
